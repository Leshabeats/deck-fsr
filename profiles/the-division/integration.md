# What the game capture verifies

In frame 3832 of *Tom Clancy's The Division* (Steam build `21161679`), the supersampling TAA dispatch precedes indexed UI draws in command order. The capture was taken on Steam Deck OLED with Proton Experimental, DirectX 12 through vkd3d-proton, and RADV. The local Radeon GPU Profiler (RGP) capture has SHA-256 `458e3ee5e84f1f8318ab9689e45d923e39b0e05be722013fd26222a81e37f6d9`.

| Recorded operation | Command ID | API PSO hash | Shader labels |
| --- | ---: | --- | --- |
| `vkCmdDispatch`, 160 × 100 × 1 workgroups | 26 | `98636e8b458c617c` | CS `454827a21acbab8d` |
| `vkCmdDrawIndexed`, representative UI draw | 108 | `8f533355bb137f81` | VS `74ebe178fa28865e`, PS `1a0534e05a13dcbe` |

Both events appear on pipe 0 in command buffer 180550. The trace contains pipeline-bind records for that same command buffer before each event. Its PSO correlation table links the API hashes to internal pipeline hashes. The compute hash identifies one ELF record. The UI hash identifies four byte-identical ELF records with Vulkan vertex and pixel shader stages in their AMDGPU metadata. The UI object's SHA-256 is `97b9930e93b908af95d05614cc8d02c7a674132aa9947aa389e52042ede6832e`. The matching vertex and fragment modules in the local Vulkan pipeline cache share three named UI interface variables. All 24 cached graphics pipeline candidates for the pair use `ONE` for source color and `ONE_MINUS_SRC_ALPHA` for destination color. The draw's active attachment remains unknown. ## Reproduce with a capture you can inspect

Open the capture in Radeon GPU Profiler and use **Events → Event timing** to locate the dispatch and draw. The **API PSO hash** filter accepts the hashes above for this capture. Use the command buffer track to compare the event order. Driver hashes can differ between captures. In another capture use the matching shader labels to identify the operations, then record the PSO hashes reported for those events. Shader labels from vkd3d-proton require `VKD3D_CONFIG=debug_utils`. ## Evidence required for the next integration step

RMV can report a Vulkan image's allocation, format, extent, mip count and assigned object name. Its resource-bind record maps an object to a memory range. The RADV RMV tokens do not identify the image view sampled by an indexed descriptor in a specific draw or dispatch. RGP adds event and pipeline data. These records do not provide the descriptor bindings or buffer contents needed by the TAA profile. [RMV texture properties](https://gpuopen.com/learn/radeon-developer-tool-suite-shader-source-code/) · [Mesa RMV token definitions](https://chromium.googlesource.com/external/gitlab.freedesktop.org/mesa/mesa/%2B/1e687cb162b9fe66f182bb42f8c5df163daeef5c/src/vulkan/runtime/rmv/vk_rmv_tokens.h) · [RADV object naming](https://chromium.googlesource.com/external/gitlab.freedesktop.org/mesa/mesa/%2B/1e687cb162b9fe66f182bb42f8c5df163daeef5c/src/amd/vulkan/layers/radv_rmv_layer.c)

An authorized replayable Vulkan capture could resolve the color, motion and depth candidates at the TAA event, including image-view mip levels, formats, and the inputs used for reprojection. Compare a stationary run and a camera pan across multiple consecutive frames to verify the jitter convention and motion scaling. Check both TAA writes and their consumers before choosing an integration point. A public Ubisoft capture or documented capture workflow for this retail build was not found. The game's built-in benchmark can provide a performance baseline.
